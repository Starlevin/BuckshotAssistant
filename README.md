# 恶魔轮盘侧边助手 v0.3

Windows 安装包请在本仓库 Releases 下载，解压整个文件夹后双击“启动游戏与助手.cmd”。需要自行拥有并安装游戏，本仓库不包含游戏程序或资源。

Windows 单人模式助手，在屏幕左侧或右侧显示本轮剩余总数、实弹数、空弹数。实时模式使用游戏启动时加载的只读观察器，每 0.1 秒读取游戏实际弹药数组并输出聚合数量；不输出子弹顺序和下一发类型，不依赖开枪动画模板。

## 使用

1. 如果游戏已经从 Steam 正常启动，请先在游戏中退出。
2. 双击 `启动游戏与助手.cmd`。启动器自动寻找本机 Steam 游戏库，同时打开游戏和侧边窗。发布包可直接启动 `BuckshotAssistant.exe --launch-game --sidebar`。
3. 进入单人游戏。主菜单、未开始本轮或未连接时显示等待或未知，不把旧局计数当成当前数量。
4. 在侧边窗选择左侧或右侧。窗口置顶，可打开主面板查看状态。
5. 玩家开枪、庄家开枪或使用啤酒退弹后，显示实际剩余聚合数量。放大镜和手锯不消耗子弹；逆转器改变类型构成而不改变总数。

`启动助手.cmd` 只打开主面板，不会给一个已经运行的普通游戏补装观察器。已通过观察器启动的游戏可以直接连接；普通游戏必须正常退出后重开，启动器不会强制结束游戏。

建议使用游戏的窗口化或无边框模式，避免独占全屏遮挡桌面侧边窗。侧边窗可覆盖游戏屏幕边缘，不会自动改变游戏画面尺寸。

## 视觉候选与策略建议

在侧边窗点“设置”，进入“视觉与策略”页。“视觉扫描（候选）”会延迟 3 秒采集所选游戏窗口，请切回游戏；“导入截图扫描”可读取本地游戏截图。识别在后台运行，不阻塞实时计数。打开“查看标注图”可以核对每个框、类别和置信度；原始候选 JSON 与标注图保存在 `%LOCALAPPDATA%/BuckshotAssistant/vision/`。

视觉采用上游约 11 MB ONNX 模型和 CPU ONNX Runtime，不使用 Torch。识别 9 类道具、实空弹与血量符号。道具暂按可调整的画面 Y 比例分敌我，默认 0.5；必须核对当前视角与分界线。子弹只有在装弹展示、全部子弹可见时才可能通过视觉清点。未检出不代表没有，且真实血量面板截图出现过道具误检。因此视觉仅提供候选，不覆盖实时计数，不自动确认道具或血量，也不自动输入策略。

“策略建议（需核对全部输入）”打开独立输入面板。必须手工填写并确认双方血量、最大血量、双方 9 项道具、手铐、手锯、玩家回合、模式范围和庄家额外记忆。缺失或不支持的状态不会计算；当前仅支持已确认范围内的单人无尽模式。后台计算有 20 秒超时，关闭面板取消计算。建议来自上游游戏树模型，部分大局面可能启发式回退；任何动作、随机结果或新信息出现后需要重新核对并计算。

集成源及 MIT 许可证见 `THIRD_PARTY_NOTICES.md` 和发布目录 `_internal/third_party/buckshot-roulette-solver/LICENSE`。上游固定版本为 `49f3511b9db7be6237329a722514f9db91756ea5`。

## 实时读取范围与数据有效性

当前支持本机 Windows 游戏 v2.2.0.6 的单人 `ShellSpawner` 数据源；多人模式尚未接入验证，不能保证显示。游戏更新改变脚本路径或变量时需重新验收。

观察器通过游戏引擎的 `--script` 参数加载外部 `game_bridge.gd`，随后载入原主场景。它不修改游戏 EXE、PCK 或 Steam 启动设置，也不写入弹药、生命等游戏变量。下次直接从 Steam 启动即不加载观察器。游戏自身仍会按正常流程保存设置和进度。

计数在游戏生成本轮弹药序列时出现，可能早于装膛动画结束；显示的是该轮剩余弹药，不是装膛动画已插入几发。弹药消耗以游戏内部移除时刻为准，动画和数字可能有短暂先后差异。

聚合心跳文件为 `%APPDATA%/Godot/app_userdata/Buckshot Roulette/buckshot_assistant_state.json`。助手检查心跳不超过 2 秒、游戏进程仍存在、数量是非负整数且总数一致。游戏退出、数据过期、菜单或读取失败时隐藏确定数字。文件只含总数、实空弹数、进程和时间戳，不包含顺序。

原 OCR/手动计数作为可选旧模式保留，需手动校准，不能与实时模式的准确性混为一谈。默认启用实时模式。旧版详细说明存于开发目录 `artifacts/README-v0.1.md`。

## 开发验证

使用 Windows 和 Python 3.11。在项目根目录运行 `./build.ps1`，会创建虚拟环境、安装依赖、运行测试并生成 `dist/BuckshotAssistant/`。GitHub Actions 提供相同的 Windows 构建与测试流程。仓库仅包含运行必需的上游引擎、模型与许可证，固定版本及来源见第三方说明。

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\build.ps1
```

`live_log.py` 验证新鲜度、进程及数量一致性；`tests/test_live_log.py` 覆盖过期/未来时间、未知状态、矛盾数量和已知零弹数。单元测试不替代真实游戏验收；实际测试证据以 `artifacts` 内保存的当前运行记录为准。

发布时保留 `dist/BuckshotAssistant` 整个文件夹，包括 `_internal/game_bridge.gd`。无需另装 Python；源码运行需要项目虚拟环境依赖。
